# Chapter 19: 配置与变更管理

## Core Idea
配置管理管"技术状态的账本"，变更管理管"基准改动的审批流程"——二者耦合，共同保证项目可追溯、可控。

## Frameworks Introduced
- **配置管理活动**：识别配置项(CI) → 控制（版本/基线）→ 状态记录 → 审计 → 发布。
- **配置库三库**：开发库（动态、频繁改）→ 受控库（基线产品冻结、受控入库）→ 产品库（最终交付、存档）。
- **基线三类**：功能基线 / 分配基线 / 产品基线（经评审冻结，变更须走流程）。
- **变更管理流程**：变更申请（书面）→ 影响评估 → 变更控制委员会(CCB)审批 → 实施 → 验证确认 → 闭环归档。

## Key Concepts
- **配置项(CI)**：受控的对象（文档、代码、硬件规格等）。
- **配置审计**：功能审计 + 物理审计，确认配置项一致。
- **变更 vs 配置**：变更关注"改动的审批"，配置关注"改动后的状态记录"。

## Mental Models
- 配置 = **技术状态账本**；变更 = **改账本的审批流**；CCB 是闸门。

## Anti-patterns
- **绕过 CCB 直接改基线**——与第8章整合管理的整体变更控制同源，是案例找错高频点。
- **开发库与受控库混淆**——未冻结的变更不能进受控库，否则失去基线意义。

## Key Takeaways
1. 配置库三库及各自状态。
2. 基线三类。
3. 变更 6 步流程 + CCB 角色。
4. 配置审计两类。
