# Chapter 9: 项目范围管理（6 过程）

## Core Idea
范围管理确保"做且只做所需工作"；**WBS** 是把可交付成果分解为工作包的层次结构，是范围基准的核心。

## Frameworks Introduced
- **6 个过程**：① 规划范围管理 ② 收集需求 ③ 定义范围 ④ 创建 WBS ⑤ 确认范围 ⑥ 控制范围。
- **需求工程产物**：需求文件、需求跟踪矩阵（需求→可交付物→测试的双向追溯）。
- **WBS**：100% 原则（含全部交付物与项目管理工作）；工作包为最底层；WBS 词典配套。

## Key Concepts
- **范围基准** = 项目范围说明书 + WBS + WBS 词典（三者缺一不可）。
- **确认范围**（外部验收） vs **控制范围**（内部边界管控）——前者是干系人验收，后者是防蔓延。
- **范围蔓延 / 镀金**：未经批准的增加 / 主动做多余功能，均禁止。

## Mental Models
- 范围 = **边界护城河**：WBS 之外的工作都是"不该做的"。
- 镀金看似讨好，实则破坏变更控制与成本基线。

## Anti-patterns
- **镀金（主动加功能）**——未走变更流程的"好心"会侵蚀范围与成本基准。
- **把确认范围当控制范围**——确认是客户/发起人验收签字，控制是内部管控偏差。

## Key Takeaways
1. 范围 6 过程名。
2. 范围基准三件套。
3. 确认范围 vs 控制范围区别。
4. WBS 的 100% 原则与工作包。
