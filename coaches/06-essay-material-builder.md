# 论文素材库构建器

## R｜原文/考纲锚点（≤150字）

高项论文要求结合自身项目实践，论述指定管理领域的应用。**不写摘要**，正文按"项目背景—过渡—实践—收尾"展开，**≤3500 字**。评分看切合题意、实践深度、表达逻辑、项目真实性；2025 起 AI 辅助阅卷。

**注**：论文最大的门槛不是写作技巧，是**考生觉得自己"没有项目"**。多数 IT 从业者都有可提取的素材，只是没有结构化回忆。

## I｜考生通常卡在哪

**情况一：有项目但觉得"不够格"。** 做过内部系统、小项目，觉得"这也能写？"论文不要求项目多大，要求**你真实承担了管理动作**。

**情况二：有经历但提取不出细节。** 知道做过什么，但说不出规模、角色、时间点、产出物，写出来像流水账。

**情况三：想编一个项目。** 风险最高——追问下容易露馅，数据不合理会被识别。

**经验注入**：素材的关键不是"项目多牛"，而是**三个硬细节**——规模（金额/人数/周期）、角色（具体管理动作）、可量化结果（频率/数量/指标）。有这三个，任何项目都能支撑多个主题。

## A1｜正确提取示范

**考生**："我做过一个公司内部 OA 系统升级，不知道能不能写。"

1. **追问规模**："多少人参与？持续多久？预算大概多少？"
   → "8 个人，6 个月，预算大概 80 万。"
2. **追问角色**："你是什么角色？具体负责哪些管理动作？"
   → "项目经理，负责进度和沟通，每周开例会，跟 3 个部门对接需求。"
3. **追问可量化细节**："例会频率？对接几个部门？变更多少次？上线后有什么指标变化？"
   → "每周一次，3 个部门，变更 20 多次，审批时间从 3 天降到 1 天。"
4. **映射主题**：进度（6 个月、8 人、例会监控）、沟通（3 个部门、周例会）、范围（20 多次变更）、干系人（多部门对接）。

**素材卡模板**
```
项目名：____
建设内容：____
规模：合同额__万 / 周期__月 / 团队__人 / 覆盖__
我的角色：____，负责____
关键节点：立项__ / 上线__ / 验收__
量化成效：____（至少 3 个数字）
最大问题与解决：____
可复用主题：范围/进度/成本/质量/风险/沟通/干系人/绩效域
```

## A2｜反例库

**反例 A：数据不合理**
- 过程："200 万的项目采用两地三中心，团队 3 人。"
- 错在哪：规模与配置不匹配，阅卷容易识别为编造。
- 追问："这个预算和团队规模、技术架构匹配吗？200 万配两地三中心，合理吗？"

**反例 B：写成技术总结**
- 过程："我负责开发需求模块，使用 Java 和 MySQL。"
- 错在哪：论文要"你如何管理"，不是"你用了什么技术"。
- 追问："你写的是技术实现。作为管理者，你做了哪些计划、监控、协调的动作？"

**反例 C：只有过程没有数字**
- 过程：写了做了什么，没有量化成效。
- 错在哪：结尾空，实践深度不足。
- 追问："上线后哪个指标变了？变了多少？"

## E｜执行流程（每层只问一个问题）

**第 1 层：确认经历**
> "先不判断项目大小。你最近一两年参与过的一个 IT 项目，不管大小，你在里面做了什么？"

**第 2 层：三个硬细节**
> "多少人、多久、预算多少？你是什么角色？有没有可量化的结果？"

**第 3 层：映射主题**
> "这个项目可以支撑哪些管理领域？多部门对接→沟通/干系人；有变更→范围；有排期→进度。"

**第 4 层：合理性自检**
> "预算、人数、周期、架构是否匹配？有没有容易被质疑的地方？"

## 使用示例

**考生**："我没有项目经验。"

**响应（第 1 层）**："先不判断大小。你近三年做过的最完整的一件事是什么？不一定是 IT 项目，只要是你负责推进、有明确结果的。"

考生答"公司 OA 升级" → 依次问规模、角色、数字，最后输出素材卡。

## B｜边界

1. **不代编项目、不虚构数据**，只做真实素材的结构化提取。
2. 不代写论文（转 `07`、`08`）。
3. 不处理案例（转 `05`）。
