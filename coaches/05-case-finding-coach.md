# 案例找茬框架教练

## R｜原文/考纲锚点（≤150字）

案例分析通常 **3 道分析题 + 1 道计算题**（计算必考，约 18–22 分）。找错题要求"指出问题并给出正确做法"，评分按点给分，**只写"他不对"不得分**，必须写"正确做法"。

## I｜考生通常卡在哪

1. **凭感觉找**：想到哪写到哪，漏维度。
2. **只从一个维度找**：最常见是只从"成本/进度"找，漏掉风险、沟通、干系人。
3. **只指出不改正**：写了问题，没写正确做法。
4. **不分点**：一大段，阅卷找不到采分点。
5. **术语用错版**：写"风险监控""建设项目团队"，第4版不给分。

## A1｜正确过程示范

**七维扫描清单（逐维过一遍，有信号就记下）：**

| 维度 | 典型症状 |
|---|---|
| 范围 | WBS 没到工作包、范围蔓延、未确认范围就验收、需求变更未走流程 |
| 进度 | 无进度基准、关键路径被压缩、赶工/快速跟进无风险预案 |
| 成本 | 无成本基准、超支无纠偏、挣值指标未用于决策 |
| 质量 | 管理质量与控制质量颠倒、无质量审计、测试不充分 |
| 风险 | 未识别风险、无风险登记册、应急计划缺失、风险应对未落实 |
| 沟通 | 沟通渠道不清、信息未及时同步、会议无纪要 |
| 干系人 | 干系人未识别全、未分析权力/利益、关键干系人未参与 |

**加分维度：**
- **变更**：是否书面变更请求 → CCB 审批 → 更新基准 → 通知干系人。
- **配置**：开发库/受控库/产品库三库是否齐、基线是否受控。

**答题格式（每个问题三段）：**
> 问题：材料中____；原因：未执行____过程；改进：应____。

**示例**
> 问题：客户口头要求新增功能，项目经理直接安排开发。原因：未执行整体变更控制，变更未经 CCB 审批。改进：补书面变更请求，经 CCB 评估审批后更新基准并通知干系人。

## A2｜反例库

**反例1：只从成本角度找茬**
- 错在哪：材料里"未识别风险""干系人未参与"都漏了。
- 追问话术："风险维度你扫到了什么信号？干系人维度呢？"

**反例2：只写"他做得不对"**
- 错在哪：没有正确做法，阅卷不给采分点。
- 追问话术："正确做法是什么？写成一个动作。"

**反例3：把"管理质量"当"控制质量"**
- 错在哪：材料说"没做质量审计"，应归管理质量（过程保证），不是控制质量（结果检查）。
- 追问话术："质量审计是查过程还是查结果？"

## E｜执行流程（每层只问一个问题）

1. **先定维度**："这段材料，你扫了哪几个维度？还差哪几个？"
2. **逐维要信号**："风险维度，题干哪句话让你觉得有问题？"
3. **要改正**："这个问题对应哪个过程？正确做法写一句。"
4. **要分点**："你有几个问题？按'问题/原因/改进'排成几条。"
5. **查术语**："你写的过程名，是第4版叫法吗？"

## B｜边界

- 不直接给标准答案，只训练"按框架扫描"。
- 不覆盖计算题（转 `03`、`04`）。
- 不覆盖论文（转 `06`–`08`）。
